# Experience First

**Apply when:** product scope or user experience is being traded against implementation convenience.

Choose the smallest coherent experience that solves the user's problem well. Do not expose internal constraints as extra user steps, confusing modes, leaky terminology, or rough behavior merely because they make the implementation easier.

When several experiences are genuinely plausible, call the Skill tool with `grilling` to resolve the product decision. When seeing and using alternatives would produce better evidence than discussion, call the Skill tool with `prototype`.

Fewer polished capabilities beat a wider set of incomplete ones. This principle cannot invent scope that the user did not ask for.

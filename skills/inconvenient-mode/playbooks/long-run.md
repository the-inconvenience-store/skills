# Long run

Read [the run checkpoint reference](../references/run-checkpoint.md) for checkpoint fields. Pick the branch the user authorized.

- **Plan only.** Record the delivery order, prerequisites, and separate proof for each unit. Name decisions that need the user. Split workstreams only where their writes are independent. Return the plan and stop. If the user wants multi-session decision work rather than a plan from agreed inputs, recommend `/wayfinder`.
- **Continue or run unattended.** Define the authorized scope, observable exit condition, and budget before starting. Use the harness's supported event or job notifications if waiting is necessary; when none exist, report the last verified state and the wake-up action instead of promising a background run. Checkpoint after each verified unit. Stop when done, the budget expires, authorization is required, or there is a genuine blocker. A stacked set of changes records the dependency and exact head per unit; a verification result belongs to the head and base it was checked against. Publishing, force-pushing, approvals, and merging are outside this route.
- **Resume.** Read the supplied handoff, plan, or workspace-scoped native history and compare it to current artifacts and heads. Reuse evidence whose inputs still match. Say where the previous run stopped, then route the remaining work. Use `/recall` when the user needs to reconstruct context across chats rather than resume from a known checkpoint.
- **Pause or stop.** Stop starting work, stand down delegated tasks, and leave work recoverable. Record the branch, worktree, outstanding changes, last proof, and first resume action. Do not commit, push, or remove work just to leave a clean status. Suggest `/handoff` when the next reader is another session.
